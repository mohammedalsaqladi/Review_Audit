# تمام | نظام المراجعة والتدقيق

تصميم أولي (Prototype) + مخطط قاعدة بيانات + سيرفر بسيط لمنصة مراجعة وتدقيق متعددة المكاتب (Multi-tenant).

## حالة المشروع الحالية

- الواجهة (public/index.html) تغطي تدفّق الاستخدام كاملاً: شاشة الأنظمة → تسجيل الدخول/إنشاء حساب → لوحة التحكم بكل أقسامها.
- شاشتا **دليل الحسابات** و**أوراق العمل** مربوطتان فعليًا بـ Supabase (قراءة وكتابة حقيقية) عبر السيرفر — بقية الشاشات (العملاء، الدردشات، العقود...) لا تزال تصميمًا تجريبيًا وتحتاج نفس نمط الربط لاحقًا.
- `database/schema.sql` مخطط قاعدة بيانات جاهز للتنفيذ مباشرة على Supabase (أو أي PostgreSQL)، يغطي: الشركات (المكاتب)، الأدوار، المستخدمين، الفروع، العملاء وملفاتهم وموظفيهم، ملفات التدقيق وموازين المراجعة، دليل الحسابات، أوراق العمل ومطابقتها التلقائية بالميزان، نقاط المراجعة، النماذج الجاهزة، العروض والعقود، الدردشات، الإشعارات، وسجل تدقيق العمليات.
- `database/seed-data-tamam.xlsx` بيانات تجريبية مترابطة لكل الجداول أعلاه، لتجربة الاستيراد ورؤية النتيجة.

## هيكل المشروع

```
tamam-audit-system/
├── server.js               ← خادم Node/Express يخدم الواجهة ويحقن إعدادات Supabase من متغيرات البيئة
├── package.json
├── public/
│   └── index.html           ← الواجهة الكاملة (المصدر الذي يخدمه السيرفر)
├── database/
│   ├── schema.sql            ← مخطط قاعدة البيانات الكامل (PostgreSQL / متوافق مع Supabase)
│   └── seed-data-tamam.xlsx  ← بيانات تجريبية مترابطة لكل الجداول، لتجربة الاستيراد
└── README.md
```

## تشغيل السيرفر محليًا (اختياري، للتجربة قبل الرفع)

```bash
npm install
SUPABASE_URL="https://xxxxx.supabase.co" SUPABASE_ANON_KEY="..." COMPANY_ID="..." npm start
```

يفتح على `http://localhost:3000` — بدون تعبئة المتغيرات الثلاثة يعمل بالبيانات التجريبية الثابتة كما هو.

## نشر المشروع على Render كـ **Web Service** (وليس Static Site)

بما أن الإعدادات صارت تُحقَن من متغيرات بيئة حقيقية عبر سيرفر، الخيار الصحيح على Render هو **Web Service**:

1. **New +** → **Web Service**، واربطه بمستودع GitHub الخاص بكم.
2. عبّئ الحقول:

| الحقل | القيمة |
|---|---|
| Branch | `main` |
| Root Directory | اتركه فاضيًا |
| Build Command | `npm install` |
| Start Command | `npm start` |

3. من قسم **Environment Variables** أضف ثلاثة متغيرات:

| Name | Value |
|---|---|
| `SUPABASE_URL` | رابط مشروعكم في Supabase |
| `SUPABASE_ANON_KEY` | مفتاح anon الخاص بالمشروع |
| `COMPANY_ID` | uuid صف مكتبكم في جدول `companies` |

4. اضغط **Create Web Service**. بعد انتهاء البناء يعطيكم رابطًا مباشرًا (مثل `tamam-audit-system.onrender.com`) والواجهة عليه تقرأ الإعدادات فعليًا من متغيرات البيئة هذه — لا حاجة لتعديل أي كود عند تغيير المشروع أو المفتاح لاحقًا، فقط تُحدَّث القيمة من لوحة Render ويعاد التشغيل تلقائيًا.

## تنفيذ قاعدة البيانات على Supabase

1. أنشئ مشروعًا جديدًا في [supabase.com](https://supabase.com).
2. من لوحة التحكم افتح **SQL Editor**.
3. الصق محتوى `database/schema.sql` بالكامل ونفّذه (Run).
4. تحقّق من تبويب **Table Editor** لرؤية الجداول الناتجة.
5. أضف صفًا واحدًا يدويًا في جدول `companies` يمثّل مكتبكم، وانسخ الـ `id` الناتج (uuid).
6. عند الحاجة لعزل بيانات كل مكتب تلقائيًا (Row Level Security)، الجداول التالية مفعّلة عليها RLS مسبقًا في الملف: `chart_of_accounts`, `wp_groups`, `wp_main_items`, `wp_sub_items`. كرّر نفس النمط على بقية الجداول عند الحاجة.

## ملاحظة حول ربط دليل الحسابات وأوراق العمل بـ Supabase

لا حاجة لتعديل أي كود يدويًا بعد الآن. بمجرد ضبط متغيرات البيئة الثلاثة (`SUPABASE_URL`, `SUPABASE_ANON_KEY`, `COMPANY_ID`) على السيرفر — محليًا أو على Render كما بالأعلى — تُحمَّل شجرتا **دليل الحسابات** و**أوراق العمل** تلقائيًا من Supabase عند تسجيل الدخول، وأزرار "حفظ" في نوافذ الإضافة (حساب / مجموعة / رئيسي / فرعي) تكتب فعليًا في القاعدة. بدون ضبطها، تعمل الشاشتان بالبيانات التجريبية الثابتة كما هي.

## الخطوات التالية المقترحة

- تعميم نمط الربط الحقيقي (المستخدم حاليًا في دليل الحسابات وأوراق العمل) على بقية الشاشات: العملاء، الملفات، نقاط المراجعة، العروض والعقود، الدردشات.
- تفعيل تسجيل الدخول الحقيقي عبر `fn_login_lookup()` و`fn_is_company_active()` الموجودتين في `schema.sql` بدل بيانات الدخول الوهمية الحالية.
- استبدال placeholder الشركة/المستخدم الحالي (`CURRENT_COMPANY_ID`) بجلسة دخول فعلية بعد ربط تسجيل الدخول بقاعدة البيانات.
- تفعيل RLS على بقية الجداول متعددة المستأجرين بنفس نمط `chart_of_accounts` و`wp_groups`.
